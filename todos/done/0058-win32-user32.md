## Goal

The windowing system: HWND tree, window classes, the message loop,
`WM_PAINT`, input routing, the standard controls, and the accessibility /
agent-query tree that makes discrete widgets `wmctl`-drivable.

## Plan

- **Classes/create**: `RegisterClass(Ex)`, `CreateWindowEx`,
  `DestroyWindow`, `DefWindowProc`; `WNDCLASS` storage; window words
  (`Get`/`SetWindowLongPtr`).
- **Messages**: the queue, `GetMessage`/`PeekMessage`/`TranslateMessage`/
  `DispatchMessage`, `SendMessage`/`PostMessage`, `PostQuitMessage`; the
  `WM_CREATE`/`SIZE`/`PAINT`/`DESTROY` lifecycle with the ordering real
  apps depend on (ReactOS/Wine as the oracle).
- **Surfaces**: top-level HWND ↔ `SURFACE_CREATE`; child controls drawn
  in-process (not surfaces), Wine-style. `WM_PAINT` damage via
  `InvalidateRect` → `BeginPaint` over the surface HDC (0057).
- **Input**: kernel input ring → `WM_MOUSE*`/`WM_KEY*` to the focused/hit
  HWND; focus/capture (`SetFocus`/`SetCapture`); `WM_COMMAND`
  notifications.
- **Standard controls**: `BUTTON`, `EDIT` (single + **multiline** —
  notepad's editor), `STATIC`, `LISTBOX`, `SCROLLBAR`; their messages
  (`BM_`/`EM_`/`LB_`). comctl32 (list/tree/tab) is a later item.
- **Dialogs + menus**: `DialogBox` + resource templates, menus/
  accelerators (staged; simple apps first).
- **Agent tree**: `EnumChildWindows` / `GetWindowText`(`WM_GETTEXT`) /
  window rects → a `wmctl` query op; `PostMessage(BM_CLICK/EM_SETSEL…)`
  for synthetic action. `wmctl click "OK"` resolves by label, not pixels
  — records OS.md's agent-target pillar.

## Acceptance

- A Petzold controls+dialog sample runs windowed in-OS.
- `wmctl click "<label>"` presses a named button headlessly (observed via
  the app's `WM_COMMAND` handler / stdout), **no pixel coordinates**.
