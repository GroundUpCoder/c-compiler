# 0404 — csmith seed 450020699: wasm run 1500x slower than native (hang-class)

- **Status**: open
- **Design**: —

## Goal

The fuzz suite's live tier flagged `fuzz/live-450020699` with `run timeout`
during the 0398 gate (2026-07-29), and the seed REPRODUCES deterministically:

- native (clang -w): checksum `65817AB` in **0.48 s**
- our toolchain: compiles clean, but the wasm run was killed at **>12 min**
  (the suite's cap is 60 s) — >1500x native, far beyond any wasm-vs-native
  factor, so a hang-class (or pathologically slow) miscompile is suspected.

Not introduced by 0398: that branch touches no compiler path (`compiler.js`
unchanged vs `ab6dcc78`; the `host.js` delta is the inert `__egress` import
stub). The live tier draws random seeds per run, so this seed simply had
never been drawn before.

Reproduce:

```
csmith --seed 450020699 --max-funcs 4 --max-block-depth 3 \
  --max-array-dim 2 --max-array-len-per-dim 4 --max-struct-fields 6 \
  --max-expr-complexity 8 --no-packed-struct -o fz.c
clang -w -Ivendor/csmith-corpus/runtime fz.c -o fz_n && ./fz_n   # 0.48s
node compiler.js fz.c -Ivendor/csmith-corpus/runtime -o fz.wasm
node --experimental-wasm-exnref host.js fz.wasm                  # >12min
```

## Plan

1. Reduce (creduce or manual bisect over the seed's functions) to a minimal
   repro of the runaway loop.
2. Root-cause the miscompile (loop-condition class? integer-width class?).
3. Fix test-first: minimal repro into `tests/unit/conformance/` (or pin as
   `knownBug` if the fix is deferred), per the conformance conventions.

## Acceptance

- The seed's program completes under the fuzz tier's 60 s cap with the
  native checksum `65817AB`.
- A conformance test guards the reduced repro.
