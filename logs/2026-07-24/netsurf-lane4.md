# NetSurf Lane 4 — broadened browser coverage + goldens + the cheap L3-deferred seeds

Lane 4 of the NetSurf stream (L1 constellation → L2 frontend → L3 app
shell): prove the fidelity that justified vendoring a real engine —
mature layout, in-tree image decode, the error-page system — and fold in
the L3-deferred seeds that were cheap AND clean. Image v159 → v160.

## New test coverage (2 kernel e2es + 5 fixtures + a generator)

`tests/kernel/test_netsurf_layout_e2e.js` — layout as EXACT geometry
(the in-test expected tables are the goldens; libnsfb fills are
solid-colour, so probes are exact-RGB with tol 4):

- `table.html`: collapsed 3×2 table of 100×50 cells — all six cell
  centres, both boundaries (x=100, y=50), right/bottom table edges.
- `flow.html`: margin/border/padding arithmetic (20+5+10 puts content
  at (35,35); border band probed on all four sides) + inline-block
  wrap (three 150×40 blocks in a 320px container: third wraps to
  line 2). NetSurf landed pixel-exact on the arithmetic first try.
- `forms.html`: control RENDERING (no submit — file-only browser).
  Each control in its own 40px strip; per-row "ink" assertions locate
  controls without pinning internal.css metrics; unchecked vs checked
  checkbox rows must differ (the check glyph itself).
- `fonts.html`: sans vs serif rows and mono vs mono-bold rows must
  render DIFFERENT pixels — with the faces absent both pairs fall back
  to the same face and the bands are byte-identical, so this is the
  "the seeded faces really load" regression guard.

`tests/kernel/test_netsurf_content_e2e.js` — the content pipeline:

- `images.html` + `img/{red.gif,green.bmp,blue.ico,orange.png}`
  (generated by the new `tools/mkwebfixtures.js`, the mkgif.js
  precedent — committed generator, deterministic bytes, no image
  toolchain; PNG uses stored-deflate blocks so no dependence on any
  deflate implementation): one 32×32 solid colour per IN-TREE decoder
  — GIF (libnsgif), BMP + ICO (libnsbmp), PNG (libpng in core) — plus
  a base64 `data:` URI GIF and a width/height-scaled GIF re-use (the
  scaled-bitmap plot path). Decoded colours asserted on the
  framebuffer at the stacked block offsets. **This closes probe
  risk-3** ("decoders compiled but not exercised in-app").
- `data:text/html,...` straight from the CLI renders (see main.c fix
  below).
- A missing `file://` path renders NetSurf's REAL error page — window
  title "Not found" (the file fetcher 404s a missing path; the query
  page titles itself from Messages), heading/body glyphs asserted, and
  the process still exits cleanly. Not a crash, not a blank window.
- Bare `netsurf` opens the baked welcome page (below): navy brand
  band, body text, and the `about:logo` netsurf.png decoded top-right
  (PNG through the resource fetcher).
- `/root/Desktop/netsurf` readlinks to `/usr/bin/netsurf`.

Test-harness note (0171 discipline): the first cut of the leg helper
echoed its markers unconditionally, so a leg whose `wait win` timed out
still printed `shot-...-ok` — driveBoot's loud-fail rule caught the
timeout, but the markers pointed at the wrong leg. Echoes are now gated
(`[ -s out.ppm ] &&`) so a failed leg cannot print success.

## Frontend fixes (gucos/main.c)

- `gucos_url_from_arg` recognized URLs by `strstr(arg, "://")` — which
  sends scheme-only urls (`data:`, `about:`) down the filesystem-path
  branch. Now a real RFC 3986 scheme test (ALPHA *(ALPHA/DIGIT/+/-/.)
  ":"). `netsurf data:text/html,...` and `netsurf about:blank` work.
- Bare `netsurf` opens `about:welcome` instead of `about:blank`. The
  about fetcher redirects to `resource:welcome.html`, which resolves
  through the respaths to the new baked page (a user drop-in at
  `~/.netsurf/welcome.html` wins, standard respath order).

## Seeds folded in (all additive; v160)

- **Welcome page** `/usr/share/netsurf/welcome.html` (`os/welcome.html`):
  gucOS-branded start page. Upstream's `welcome.html` is a wall of
  http:// links — useless in a file-only browser — so this one is
  authored for what v1 can actually do: file:/data: links (including a
  `file:///root/` directory-listing link — dirlist.c is compiled),
  the history/scroll keys, openwith. Dogfoods serif headings and the
  `about:logo` PNG. Verified visually.
- **Desktop icon** `/root/Desktop/netsurf` → `/usr/bin/netsurf` (user
  section, the standard app-link convention; drive.js's deskEntries
  derives the icon-grid model from image.json, so the desk tests
  re-derive automatically).
- **Serif faces** `/usr/share/fonts/serif.ttf` / `serif_bold.ttf` =
  NotoSerif-{Regular,Bold} (OFL, sha256 in vendor/fonts/README.md).
  NOTE: the L3 spec said "4 files incl. italics" but gucos/font.c has
  only TWO serif slots (`FB_FACE_SERIF`, `FB_FACE_SERIF_BOLD` — no
  serif-italic in the framebuffer face table it ports), so two files
  is the complete fill, not a cut.
- **Bold mono** `/usr/share/fonts/mono_bold.ttf` = NotoSansMono-Bold
  (fills `FB_FACE_MONOSPACE_BOLD`; term/wm keep the regular face).

Additive imgdiff (bake origin/main manifest vs lane, --packages=all):
onlyA = []; onlyB = the 4 system seeds + `/usr/share/desktop/default/
netsurf` (derived by the Lane-D desktop-defaults bake from the new
user-section link). Content diffs on common paths: `/bin/netsurf` (the
main.c change), `/usr/share/os-release` (v160), `/opt/quake/quake-bin`
(the known `__TIME__` bake nondeterminism, same size). Nothing else.

## NOT wired (found, noted, not faked)

- **JPEG**: no `WITH_JPEG`, no vendored libjpeg — the mime map knows
  `.jpg`/`.jpeg` but no image handler registers for the type, so a
  jpeg `<img>` stays an unrendered object. Deliberately NOT covered by
  a test-passing workaround; a libjpeg(-turbo) port is a candidate
  follow-on if jpeg pages matter.
- `about:credits`/`about:licence` redirect to resource pages that are
  not seeded (upstream keeps them under `resources/en/`); the welcome
  page deliberately doesn't link them.
