Settled recommendations for the requested boundaries:
1. Multi-reader identity: accept an explicit owner-held opaque object token shared only by readers of the SAME underlying live inode namespace. Equal bytes, snapshots/forks or overlapping inode values alone are insufficient. Token is trusted embedding authority, not proof the implementation can validate from content. Reject primitive/invalid tokens, contradictory registrations for one fs object and duplicate exact-fs-instance mounts before installing mutable mount hooks. Existing hooks6196+ make the latter unsafe; do not advertise new bind-mount support. Separate readers plus one explicit key can be supported, with equality tests and distinct-copy negative controls. Device IDs need only be comparable inside the declared one-owner namespace, not across independent kernels or reboots.
2. Missing RO identity: accept disabling the ENTIRE optional local path when authority is absent, keeping reads/stat/fds consistently brokered. Contradictory or malformed explicit identity must fail construction before workers; never local dev0 fallback. Test missing metadata with real brokered operations, not just _ro===null. Validate exact configured readonly mount and fresh worker descriptor; include warm reuse and promotion/inheritance equality. Trusted SAB-to-volume correspondence must remain an explicit embedding precondition; independent byte authentication is not promised.
3. Native Node adapter: separate scope is reasonable because host272 is a different adapter and native widths introduce ABI overflow policy. Track it explicitly before completion; no universal stat-identity claim. Anonymous pipe/socket/console identity may also be a separately tracked slice. However strict new serializers must not make their existing fstat unexpectedly throw: give excluded producers explicit documented dev0 metadata and retain their current behavior, or implement that slice deliberately. No blanket missing-dev fallback that masks mounted producer bugs.
4. Invalid metadata: specify configuration/programmer-error rejection versus ordinary syscall failure concretely. Mount-ID exhaustion must refuse without wrap or partial mount-hook installation. High-bit and max-u32 C/WASI adapter tests are useful; test noninteger/negative/overflow/missing inputs separately, and avoid partial output writes before validation. Native representability errors belong to the deferred adapter policy, not guessed identity remapping.
