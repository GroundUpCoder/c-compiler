### Smoke composition — why these members

Chosen against the Batch 1 measurements (the gate's long poles are
`test_os_boot.js` ~710 s and the 200 s+ sweep members):

- The cheap native suites (todos 7 s, netsurf-patch 2 s, unit 16 s,
  host 39 s warm) + blockfs (85 s) — compiler, fs, harness, register.
- `disw` — the cheapest run.py category (~1 s): proves the pinned-python
  plumbing (#483) launches a real interpreter end to end.
- A filtered kernel leg (9 files, 2.9 s + fixture check): the SAB protocol
  core (`test_kernel.js`), line discipline + real-C e2e (`test_tty*`), pipes
  incl. the SPSC ring + real-C pipelines (`test_pipes*`), brokered fs with
  real C (`test_fs_e2e`), WM mechanics (`test_wm.`), and **one real
  fixture-boot e2e** (`test_strace_e2e.js`, ~1.1 s warm — a full in-OS
  session: spawn, trace, signals, exit-status propagation). So smoke really
  compiles C, really runs it under host.js/worker_threads, and really boots
  the OS.
- **The sweep is deliberately OUT** (a recorded, guard-pinned decision, not
  an oversight): its floor is Chromium + serve + bake ≈ minutes, the
  headless boot covers the kernel/OS core, and browser-touching edits pull
  `sweep` through the diff tier's #428 rules anyway. If policy changes, the
  guard check flips WITH the tier.

lane iterating on a host-mapped change actually waits on.

## The anti-lie mechanisms (the point of the design)

A tiering system's failure mode is a green that means "we didn't run the
thing that would have failed". Four mechanisms, all pinned by
`tests/host/test_diff_rules.js`:

1. **Registry set-equality, both ways** (`SUITES` ↔ `ALL_SUITES` ↔
   `TIERS.full.suites`) — the #314 shape at dispatcher level. A suite added
   to `SUITES` but forgotten from `ALL_SUITES` used to silently vanish from
   `all`; now it goes guard-RED, and `full` cannot narrow.
2. **Filter-token liveness.** Smoke's kernel members are selected by
   substring token; a renamed/deleted test would silently shrink the tier to
   a green no-op. The guard checks every token against the on-disk tree with
   the suite runner's own matcher (`matchesFilter`), pins the fixture-boot
   leg (`test_strace_e2e.js`) and the SAB core (`test_kernel.js`) by name,
   and pins `test_os_boot.js` (the ~710 s bake-path test) OUT so an
   over-broad token can't silently turn the 5-minute tier into a 15-minute
   one.
3. **The record states its tier.** `build/test-run/summary.json` gains
   `tier`, `tierFilters`, `omitted` (verified present in the smoke run's
   record). Rule 5's ship-gate reading is unchanged and still sufficient on
   its own: a tier run has a partial `suites` list, and a tier-filtered
   kernel run writes its child artifact with a non-null `filter` — neither
   can impersonate a full gate.
4. **`full` refuses the softening flags.** `--filter` and `--resume` exit 2
   with a named fix (rule 5: unfiltered, no-carry). `all` keeps the legacy
   permissive behavior for hand-driven work. Also refused, all at exit 2:
   `smoke --filter` (the per-suite filters ARE the tier's definition),
   tier+named-suites, tier+`--diff`, tier+tier.

On stdout, a tier run prints what it deliberately did NOT run twice — at the
banner and again at the verdict line (`tier: smoke — NOT a full gate
(deliberately not run: …)`), and the kernel row shows
`[9/169 files — PARTIAL]` in yellow via the existing 0339 coverage line.

## Negative control (acceptance evidence)

Deliberately mis-declared the smoke boot-leg token
(`test_strace_e2e` → `test_ztrace_e2e` in `SMOKE_KERNEL_FILTER`), ran the
guard:

```
FAIL smoke kernel filter token "test_ztrace_e2e" matches >=1 on-disk file (a dead token silently shrinks the tier) — 0 file(s)
FAIL smoke kernel filter selects test_strace_e2e.js (the real fixture-boot leg)
2 check(s) FAILED
GUARD_RC=1
```

Reverted the token:

```
All checks passed
GUARD_RC=0
```

So a test that should be selected by a tier cannot be silently dropped: the
drop is a RED host suite, which every diff touching `tests/run.js` selects
(the existing self-gating rule).
