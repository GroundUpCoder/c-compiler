# Combined libc lane — todos/0382 + todos/0325 Groups A/B

Two tickets, one lane, one gate. The symbol overlap (`gmtime_r`, `tzset`, `timegm`, the
`*at` family) is larger than it looks, so two lanes would have meant either double
implementation or a cross-lane ownership negotiation costing more than the merge.

## The probe earned its keep on its first run

`todos/0382` plan step 1 asks for a compile probe **with a positive control**, because a
sweep whose entire output is "not found" cannot distinguish absence from a broken harness.
`tools/libcprobe/probe.js` carries positive *and* negative controls and exits 2 (run void)
rather than 1 (gaps found) when either fails.

On the very first run the `open` positive control read ABSENT. That was not a harness bug:
**`<fcntl.h>` declared `open()` without pulling the TU that defined it**, so the
POSIX-correct include set failed at *link* time and only ever worked because `<stdio.h>`
happened to be included too. Without the control that would have been invisible — and with
a naive two-verdict probe it would have looked like `open` was simply missing. Hence three
verdicts: `absent` / `decl-only` / `present`. `decl-only` went on to catch the same shape
again in `<unistd.h>` when the `*at` declarations landed ahead of their
`__require_source`.

Baseline on `3df5d28f`: 48 gaps, 5 controls OK.

## Writing behaviour tests found two defects older than the lane

Both tickets insist on behaviour tests, not linkage tests. That is the only reason these
surfaced — a linkage test for `umask` would have passed against both bugs.

1. **`BlockFS.open` applied a hardcoded `& ~0o022`**, with a comment describing it as "the
   single-user system has a fixed 022 umask ... there is no per-process umask in the fs".
   A *process* mask living in the *filesystem*. It composes with the real one, so
   `umask(0)` could never produce the `0666` POSIX promises. Removed. The libc's initial
   mask is `022` — precisely the value the fs was applying — so every caller that never
   touches `umask()` observes byte-identical modes. That symmetry is what made the fix
   safe to land in one step.
2. **`BlockFS.mkdir` accepted a `mode` argument and discarded it.** Every directory came
   out `DEFAULT_DIR_MODE`, so `mkdir("/priv", 0700)` silently produced a world-readable
   `0755`. Regression test: `tests/unit/blockfs_mkdir_mode`.

## fma: emulated, and the emulation had to be proved

WebAssembly has no fused multiply-add, and the whole point of `fma` is that `x*y+z` rounds
*once*. Shipping the naive form under that name is the exact failure both tickets forbid,
so this was developed against a differential harness rather than by inspection. The
iteration is worth recording:

| version | mismatches / 4,000,010 |
|---|---|
| double-double, scale into the product's frame | 332,996 — all extreme-exponent, `ldexp` overflowing |
| + common dominant frame with a sticky clamp | 2 — both subnormal results |
| + additive round-to-grid constant | 2 (unchanged; the constant only works for `\|r\| < 2^(gexp+51)`, which this range violates, and my ties-to-even test was a tautology) |
| + exact integer-grid rounding | **0** |

Final: 0 mismatches over 6,000,010 inputs across four regimes (adversarial fixed cases,
near-1.0 double-rounding, full-range random bit patterns, subnormal-heavy). The committed
test pins 72 clang-generated cases **and a case where naive and fused demonstrably
differ**, so it fails against a stub instead of passing vacuously.

Compared as raw bits, not `%a`: C99 leaves the leading hex digit of a subnormal
unspecified, so the two printfs legitimately disagree on formatting — text comparison
reported a difference that was not there, and would equally have hidden a real 1-ulp one.

## Where we deliberately follow Linux over macOS

Three test lines differ from clang-on-macOS, each a genuine implementation-defined fork,
each documented at the assertion:

- `umask(07777)` reads back `0777` (Linux masks with `S_IRWXUGO`) vs macOS's `7777`.
- `wcstol(L"0x", 16)` consumes 1 char — C says the subject sequence is the *longest* valid
  initial subsequence, which with no hex digit is just `"0"`. glibc agrees; BSD consumes 0.
- `fchmodat(..., AT_SYMLINK_NOFOLLOW)` is `ENOTSUP` (Linux) vs macOS's 0 (BSDs track
  symlink modes).

Everything else that could be cross-checked is byte-identical to clang: all 72 fma cases,
all 9 `gmtime_r` dates, 21 of 22 `*at` legs, all `isascii`, 12 of 13 `umask`.

## Two things NOT done, on purpose

**`mkfifo` (0382 gap 9) is absent, not stubbed** — `todos/0401`, register `L59`. This
ticket's own plan step 4 is the argument: a link-testable `mkfifo` that cannot rendezvous
is *worse* than none, because an autoconf probe finds the symbol, sets `HAVE_MKFIFO`, and
the failure moves from configure time to run time. libarchive's `archive_write_disk` — the
concrete consumer from `0350` — would start attempting FIFO restores that cannot work.
Real FIFOs need kernel rendezvous, not a libc line. **`todos/0382` therefore stays open**,
blocked on `0401`; 8 of its 9 gaps shipped.

**The `*at` family's dirfd resolution mode is unreachable** — `todos/0400`, register `L58`.
No fd here can refer to a directory (`BlockFS.open` answers `EISDIR`, no `O_DIRECTORY`,
`opendir` uses a disjoint handle namespace). `AT_FDCWD` and absolute paths are exact; a
real dirfd gets `ENOTDIR`, or `EBADF` if the fd is closed — both *literally true* for
every fd this system can produce, so the family is correct rather than special-cased. All
ten calls route through one `__at_ok()`, so when directory fds land that is the single
function that changes. Directory fds are an fs/kernel capability spanning BlockFS, MountFS,
kernel OFDs, RemoteFS local-fd promotion and spawn fd-actions — a different kind of work
from a libc header gap, which is why it is ticketed rather than absorbed.

## Smaller calls

- **`getentropy` is a host import, not a `/dev/urandom` read.** The `/dev/urandom` version
  worked on v4 and *failed on v3*, because the device nodes are materialised only on a v4
  mount. Routing a security-relevant primitive through filesystem layout is wrong, and the
  v3 failure proved it was not hypothetical. `__getentropy` sits in the runtime env next to
  the clock imports, so it works in every flavour. It still FAILS rather than degrading if
  the host has no CSPRNG.
- **`__mkdir_impl` is an ADDITIVE host env alias.** `mkdir` had to become a real libc
  function to apply the umask, but the plain `mkdir` env name is the wasm-ld ABI the clang
  toolchain links against, so nothing was renamed out from under it.
- **`__timespec.h`** gives `<sys/types.h>` and `<time.h>` one definition of `time_t` /
  `struct timespec` / `clockid_t`. Not `<sys/types.h>` including `<time.h>`: that carries
  `__require_source("__time.c")`, and `<sys/types.h>` is included by nearly everything, so
  it would link the whole time TU into every binary that merely names a `size_t`.
- **`open()` moved to a new `__posix.c`**, which `<fcntl.h>` requires. Requiring
  `__stdio.c` from `<fcntl.h>` instead would have pulled all of stdio into every
  fcntl-only binary — and the `tools/zipmeasure` measurement already established that the
  linker does **not** drop unreferenced TU functions, so that is real bytes.

## Two goldens updated (neither a behaviour change)

- `unit/printf` pinned the **address of a string literal** via `%p`, so it broke on any
  libc data-segment growth while testing nothing about `%p`. Now pins a fixed pointer
  value: same formatting coverage, stable forever.
- `switch_br_table` enumerates every switch lowering in the whole link, libc TUs included.
  The new entries confirm the heuristic still works — `strsignal`'s dense 29-case switch
  chose `br_table`, `pathconf`'s sparse 6-case chose `br_if`.

## Image bump: 186 → 187, owed

`compiler.js`'s libc is compiled INTO every seeded binary, so every baked binary's bytes
changed. The concrete hazard is not cosmetic: a persistent browser OPFS image only
re-fetches on a version bump, while `host.js` is a static asset with no version gate. A
stale image plus new `host.js` means old binaries — which expect the *filesystem* to apply
`~022` — running against a host that no longer does, i.e. directories created with
unmasked modes.

## The ksvc text service had to learn the new imports

`os/ksvc.js` loads `/usr/lib/ksvc.wasm` under a deliberately **minimal read-only** env.
`<unistd.h>`, `<fcntl.h>` and `<sys/stat.h>` all pull `__posix.c`, and the linker does not
drop unreferenced TU functions, so the `*at` family's imports (`rmdir`, `unlink`, `rename`,
`link`, `symlink`, `readlink`, `chmod`, `realpath`, `ftruncate`, `stat`/`lstat`/`fstat`,
`__utime`, `__gettimeofday`, `__mkdir_impl`, `__getentropy`, `__nanosleep`) appeared in
ksvc.wasm even though ksvc calls none of them. Boot died with a bare
`LinkError: Import #13 "c" "rmdir": function import requires a callable`.

They are registered as `trap()`s, not no-op stubs — the file's existing pattern, and the
right one: a text service must not quietly acquire the ability to write, and if one were
ever reached the correct outcome is a loud throw naming the call. One trap in the first
draft was `access`, which ksvc **serves for real**; since the trap sat later in the object
literal it would have shadowed the working implementation and broken font loading. Caught
before commit, but it is the reason to write these as an explicit block rather than a
blanket fill.

## Size cost of __posix.c landing in every binary

Measured rather than assumed, since `todos/0350` established that this linker keeps
unreferenced TU functions. A minimal program including `<stdio.h> <unistd.h> <fcntl.h>
<sys/stat.h>`:

| compiler | bytes |
|---|---|
| `origin/main` | 7,960 |
| this branch | 8,808 |

**+848 bytes** per binary. Against a 106.7 MiB image with ~100 binaries that is under
100 KB total, well inside the noise band the 0350 ruling works in — but it is a real cost
and it is why `open()` moved into `__posix.c` rather than `<fcntl.h>` requiring all of
`__stdio.c`, which would have been far larger.
