# 0413 — the first Rust binary runs in gucOS

The Rust program (`todos/RUST.md`) starts here. This entry records the
decisions and the confirmations behind the landing.

## What landed

- A sibling repository at `~/git/gucos-rust` holds the Rust crates. It is
  local-only: it has no remote, so the ticket's `## Result` ledgers its HEAD
  (`1bcf3e37…`). ⚠️ **This sentence is SUPERSEDED — see the addendum at the
  foot of this log. It was true when the lane measured it.** The `RUST_ROOT` env var in `tests/kernel/test_rust_e2e.js`
  is the one point that resolves the sibling path. A rename of the sibling
  is a one-line change.
- The committed fixture `tests/kernel/fixtures/hello-rust/hello-rust.wasm`
  (887 bytes, sha256 beside it) is the artifact of record. The repo-wide
  `*.wasm` ignore rule gained one explicit exception for it.
- `tests/kernel/test_rust_e2e.js` fixes the ABI contract with tests. The
  unconditional legs need no `rustc`, so a normal kernel run always proves
  in-OS execution — the vacuous-leg pattern of `todos/0287` does not enter.

## Why the shape is what it is

- **The panic handler calls `__exit(101)`.** The probe shipped `loop {}`,
  which hangs the process. The test bounds the panic run with a timeout, so
  a regression to a hang fails loud. 101 is the status that std Rust uses
  for a panic.
- **`alloca` is a bump allocator over a static arena, here only.** The crate
  has no allocator, so the arena is memory that no `malloc` claims. This is
  the scoped exception to `RUST.md` §3 rule 3, and `todos/0414` replaces it
  with a `malloc`-backed export. The hand-off note sits in the crate source.
- **The fixture is byte-deterministic.** `codegen-units = 1` in the release
  profile, proven by a clean rebuild. Without determinism the freshness leg
  (rebuild, compare bytes) could not exist, and a fixture with no freshness
  check rots quietly.
- **The fixture itself carries the panic path.** `hello-rust.wasm panic`
  panics on purpose. This puts the panic contract inside the unconditional
  legs: the estate proves it without `rustc`, both under `node host.js` and
  from the shell of a booted OS (`prc=101`).

## Measured confirmations

- Stable `rustc 1.96.1` links a defect crate (an extern block without
  `#[link(wasm_import_module = "c")]`) to a LINK FAILURE that names the
  symbol: `undefined symbol: write`. The emitted linker command line shows
  no `--allow-undefined`. The ticket's Trap 2 premise holds as stated.
- A module with no `alloca` export exits 1 under `node host.js` with
  `alloca is not a function`, before `main`. Trap 1 holds as stated.
- The in-OS spawn works through the plain shell path: inject the wasm into
  the root volume (the menubox/oomdlg pattern), then `/root/hello-rust.wasm`
  at the hush prompt. The `\0asm` magic dispatch needs no change.

## Out of scope, by sequencing

The browser leg needs the module inside the image, and the image takes it
only through the packaging seam — that is `todos/0416`. The base image
ships no Rust (`RUST.md` §3 rule 5).
