# lane-530511 — #530 layered GCODE.md + #511 native signal-before-poll race

One lane, one gate: both tickets edit `os/gcode/gcode.c` (#530 the system-prompt
construction, #511 the native `run_command`), so they can never run as parallel
lanes. Commits: #511 first (`173f5a13`), #530 on top (`b8968569`).

## #530 — the decisions that needed making

**Layering semantics: CONCATENATE, not override.** The cfgstore precedent fixes
the layer *set* (`/usr/share` > `/etc` > `~/.config`), but cfgstore's per-key
override does not transfer to freeform prose: an `/etc/gcode/GCODE.md` that
silently *replaced* the shipped platform file would discard the measured #505
orientation to add one line. Claude Code's CLAUDE.md layers concatenate — and
"however it is that claude code does it" is jku's own spec. A user layer
(`~/.config/gcode/GCODE.md`) is included because both precedents have one.

**The `system_prompt_hash` coupling (design point ii): context EXCLUDED from
the hash.** `cfg.system_prompt` stays the base literal / `--system-prompt`
value and is what both hash sites consume, unchanged; the loaded context is a
separate `cfg.system_sent` string built once at startup and only the request
body reads it. So the resume warning keeps its old meaning ("the base prompt
changed") by construction, and editing a project GCODE.md never fires it —
asserted by a smoke leg plus a negative control proving the warning itself
still works. What was loaded is recorded as `session_meta.context_files`.

**The literal lost ALL platform content, not just the SDL block.** The
inherited #551 scope says the SDL rule moves to the file layer; but "running
inside gucOS" and "the C compiler is `cc`" fail the same test — jku's ruling is
that a gcode running elsewhere must not inherit the platform steer. The shipped
`/usr/share/gcode/GCODE.md` (source `os/gcode/GCODE.md`, baked via image.json
v246) now carries the identity, the #505 facts, and the #551 SDL rule pointing
at `/usr/share/doc/sdl-gucos.md`; the step2 e2e asserts the rule appears in the
outgoing system prompt exactly once (moved, never duplicated).

**Budget in emission order.** 48K total cap consumed general-first: the shipped
orientation can never be starved by a giant project file; the file crossing the
cap gets an in-band marker + stderr warning, later files drop with a stderr
warning. Walk-up bounds: 32 dirs, stop at `$HOME`, a mount boundary, or `/`.

**$HOME matched by inode, not string.** Found live: macOS `os.tmpdir()` spells
`/var/...` while `getcwd` resolves the `/var -> /private/var` symlink, so a
string compare sails past `$HOME` and reads ancestor files it must not. dev+ino
comparison is symlink-proof and needs no `realpath` in the gucOS libc (where
`st_ino` is real and `st_dev` is always 0, so the match degrades to bare inode
equality — fine within one volume, which is where `$HOME` walks live).

## #511 — mechanism and testability

Self-pipe over pselect: keeps `poll`, no signal-mask management around the
loop, and race-free by construction (a byte written by the handler makes a
signal *before* poll indistinguishable from one *during* it). Nonblocking +
CLOEXEC; failed init degrades to fds of -1, which poll ignores — every failure
mode is the pre-#511 behavior, never a broken loop. Native only; the gucOS
path has no such race (handlers only at import returns).

**Severity note:** the ticket's "worst case the whole remaining wall-time cap"
predates the #507 slice clamp — the code bounds the latent ^C at ~1s
(`slice = min(1000, remain*1000+100)`). Real, but 1s, not minutes.

**Deterministic-ish test:** the race window is microseconds and unreachable
from outside the process, so `GCODE_TEST_INTR_BEFORE_POLL=1` (the
GCODE_BASH_SECS seam precedent) raises SIGINT inside `run_command` exactly
between the loop-top check and poll. The discriminator is an annotated
DIFFERENTIAL timing assertion (raced run vs a same-shape control, 800ms margin
riding on the control): the pre-fix floor is a hard +1000ms because poll always
sleeps its full slice. Red control measured by neutering `intr_pipe_init()`:
1107ms vs 107ms control — only the timing check went red.
